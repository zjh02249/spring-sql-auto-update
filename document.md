Flyway-Digital

**轻量级、Flyway-Compatible SQL 迁移工具设计文档**

------------------------------------------------------------------------

1\. 项目背景与目标

1.1 背景

Flyway 是一个成熟的数据库迁移工具，但在以下场景中存在不足或不适用性：

- 内网环境，无法引入完整 Flyway 依赖

- 国产化 / 私有化项目，需要完全可控的迁移逻辑

- 对数据库兼容性抽象需求不高

- 只需要 SQL 顺序执行 + 历史记录能力

因此，本项目设计并实现一个 **Flyway-compatible 的轻量级 SQL
迁移工具**，仅实现 Flyway 的核心迁移能力。

------------------------------------------------------------------------

1.2 项目目标

实现一个：

- **行为类似 Flyway Core**

- **History 表结构与 Flyway 保持一致**

- **不做数据库方言适配**

- **Java 1.8+ 可用**

- **可打包为独立 JAR / Spring Boot Starter**

的 SQL 版本迁移工具。

------------------------------------------------------------------------

2\. 设计原则（非常重要）

1.  **只做迁移框架，不做 SQL 兼容**

2.  **约定优于配置**

3.  **行为可预测、可追溯**

4.  **与 Flyway 语义保持一致，但不强制 API 兼容**

5.  **工程边界清晰，拒绝隐式"智能"**

------------------------------------------------------------------------

3\. SQL 迁移规则设计

3.1 SQL 文件命名规范（强约束）

所有迁移 SQL 文件必须遵循以下命名规则：

V{version}\_\_{description}.sql

示例：

V1.0.1\_\_test.sql\
V2.0.0\_\_first_init.sql\
V2.0.0.3\_\_table1.sql

version 规则

- 仅允许数字与 . 组成

- 支持多段版本号（如 2.0.0.3）

- 采用 **语义版本排序**

  - 逐段数字比较

  - 非字符串排序

description 规则

- 位于 \_\_ 与 .sql 之间

- \_ 在写入 history 表时转为空格

------------------------------------------------------------------------

3.2 SQL 扫描规则

- 扫描用户配置的目录（如 classpath:db/migration）

- 不关心数据库类型

- 不做 SQL 内容解析

- 每个文件作为一个独立迁移单元

------------------------------------------------------------------------

4\. SQL 执行与迁移流程

4.1 启动时序

在**数据源初始化完成后**执行迁移：

1.  获取 DataSource

2.  检查 flyway_digital_history 表是否存在

3.  若不存在 → 自动创建

4.  读取历史迁移记录

5.  扫描并排序 SQL 文件

6.  执行未迁移的 SQL

------------------------------------------------------------------------

4.2 执行规则

- 按 version 升序执行

- 每个 SQL 文件：

  - 在一个独立事务中执行

  - 成功：提交事务，记录 success=1

  - 失败：回滚事务，记录 success=0，停止后续迁移

- 不允许并发执行

------------------------------------------------------------------------

4.3 跳过规则

- 已存在 success = 1 且 version 相同的记录 → 跳过

- 若存在 success = 0 的历史记录：

  - 默认不自动修复

  - 是否重试由配置决定（未来扩展）

------------------------------------------------------------------------

5\. History 表设计（完全固定）

5.1 表结构（MySQL 示例）

CREATE TABLE \`flyway_digital_history\` (\
\`installed_rank\` int(11) NOT NULL,\
\`version\` varchar(50) DEFAULT NULL,\
\`description\` varchar(200) NOT NULL,\
\`type\` varchar(20) NOT NULL,\
\`script\` varchar(1000) NOT NULL,\
\`checksum\` int(11) DEFAULT NULL,\
\`installed_by\` varchar(100) NOT NULL,\
\`installed_on\` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,\
\`execution_time\` int(11) NOT NULL,\
\`success\` tinyint(1) NOT NULL,\
PRIMARY KEY (\`installed_rank\`),\
KEY \`flyway_digital_history_s_idx\` (\`success\`)\
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

------------------------------------------------------------------------

5.2 字段语义（必须严格遵守）

  ----------------------------------- -----------------------------------
  字段                                语义说明

  installed_rank                      全局执行顺序号（max + 1）

  version                             SQL 文件中的 version

  description                         description（下划线转空格）

  type                                固定为 SQL

  script                              SQL 文件名

  checksum                            SQL 内容 CRC32

  installed_by                        当前数据库用户名

  installed_on                        执行完成时间

  execution_time                      执行耗时（毫秒）

  success                             1 成功，0 失败
  ----------------------------------- -----------------------------------

------------------------------------------------------------------------

6\. Checksum 规则

- 使用 **CRC32**

- 对 SQL 文件内容（原始文本）计算

- 不做格式化、不忽略注释

------------------------------------------------------------------------

7\. 数据库兼容性设计声明（核心设计点）

flyway-digital **不尝试解决不同数据库之间的 SQL
兼容问题**。工具仅负责：SQL
脚本的数据库兼容性由使用者自行保证。当项目需要支持多种数据库时，应为不同数据库维护不同的
SQL 迁移目录。

------------------------------------------------------------------------

8\. 配置设计（最小集）

flyway-digital:\
enabled: true\
locations: classpath:db/migration\
table: flyway_digital_history\
baseline-on-migrate: false

------------------------------------------------------------------------

9\. 启动与集成方式

- 支持 Spring Boot 自动装配

- 在 DataSource 初始化完成后自动执行

- 可通过配置禁用自动迁移

- 不依赖 Flyway 本身

------------------------------------------------------------------------

10\. 技术约束

- Java 1.8+

- 不使用 Java 9+ 特性

- JDBC 执行

- 可打包为独立 JAR

- 可作为 Spring Boot Starter 引入

------------------------------------------------------------------------

11\. 明确不支持的功能（非目标）

- Undo / Rollback

- Repair

- Callback

- 多 Schema

- 并发迁移

- SQL 内容解析

- Flyway API 兼容
